The model proposes, code checks

Language models are good at judgement and bad at hard constraints. Engineering work is full of hard constraints. So my systems split the two:

  1. The model proposes: a plan, an answer, a routing, a classification.
  2. Deterministic code checks it against real data and rules: clearances, sources, budgets, schemas.
  3. Problems go back to the model as a precise list, in a bounded repair loop.
  4. If it still fails, the system says so, and shows what is open, instead of guessing.

Document AI · open source

Truth-aware RAG: answers that know current facts from superseded ones

Engineering documentation is full of values that were true once and have since been superseded. Standard RAG retrieves them anyway. My pipeline weights each source by whether it is current, archived or a log entry, fuses BM25 and vector search, cites every claim and refuses when unsure. It ships with an evaluation that also finds stale statements in the documents themselves. Measured against plain hybrid search on a real 121-document hardware project:

AI for hardware engineering · my own toolchain

AI-driven PCB design pipeline

A set of Claude Code skills that take a board from schematic to fab files in EasyEDA Pro. The design checks are gated: each IC is verified against its reference design, and the netlist is reconciled before layout. The EDA connection cannot draw tracks, so I wrote an offline layer that reads the board file directly. It converts the board for the Freerouting auto-router, brings the result back, and runs an exact clearance and connectivity check before anything touches the real board. Every write is backed up and read back. The final step re-checks part stock and exports Gerber, BOM and pick-and-place files for JLCPCB.

AI product · built solo, live

StemBot: an AI research mentor for STEM students

Students starting a research project often struggle alone with a vague question and too much literature. StemBot guides them from refining the research question through methodology to presenting results. It keeps each project's context across sessions and reads the papers and documents they upload. I built the whole product: a Next.js/TypeScript app, Supabase for authentication, a Postgres database with row-level security and file storage, an LLM back end, and Stripe for free and paid plans with monthly usage limits and a customer portal.

Debugging that mattered. One settings page hung for some users. The cause was more than 290 Supabase client instances racing over the login state, plus queries that worked against row-level security instead of with it. One shared client and policy-based queries fixed it.

Open-source tools rebuilt for AI agents · early preview

RootPLC: an agent-first PLC toolchain

Industrial tools were built for people clicking through an IDE. Agents need the opposite: a command line, machine-readable output with stable error codes, and checks they cannot talk their way past. RootPLC is an open IEC 61131-3 compiler, simulator and runtime in Rust, built that way. An agent connects through an MCP server, writes Structured Text, and gets diagnostics with fix hints. It runs tests in a deterministic VM, with mutation testing to show whether those tests would catch a change. It simulates controller and plant together on a virtual clock, then produces an evidence pack for sign-off. Deployment needs a human's approval.
